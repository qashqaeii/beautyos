# BeautyOS — فاز ۶، گام اول: هسته اشتراک پلتفرم

## محدوده پیاده‌سازی

- مدل `SubscriptionPlan`: کد یکتا، نام، مبلغ به تومان، دوره روزانه، روزهای آزمایشی، فعال بودن و توضیح.
- مدل `SalonSubscription`: یک اشتراک برای هر سالن؛ پلن، وضعیت، تاریخ شروع/پایان، پایان آزمایش و لغو.
- نمایش فقط-خواندنی در `/control/subscriptions/` برای مدیر مرکزی فعال و Superuser.
- مدیریت داده‌ها از Django Admin با دسترسی محدود به مدیر پلتفرم.
- داده موجود سالن‌ها بدون اشتراک‌سازی خودکار باقی می‌ماند و هیچ محدودیت دسترسی بر آن‌ها اعمال نمی‌شود.
- هیچ پلن یا قیمت ساختگی به‌صورت seed وارد دیتابیس نمی‌شود.

## مرزهای ضروری

- `apps.finance.Payment` درآمد خدمات داخل سالن است، **نه دریافتی اشتراک BeautyOS**. از آن برای تسویه اشتراک استفاده نشود.
- مدل‌ها در این گام **هیچ وجهی دریافت نمی‌کنند**، تراکنش تأییدشده یا رسید مالی صادر نمی‌کنند.
- وضعیت اشتراک در این گام **توصیفی** است؛ پیش از تکمیل چرخه پرداخت و قواعد grace period، جلوی دسترسی سالن را نمی‌گیرد.
- ارسال پیامک، فعال کردن درگاه یا دیپلوی Production انجام نمی‌شود.
- تمام تاریخ‌ها در پایگاه داده timezone-aware ذخیره می‌شوند و UI از فیلترهای تاریخ شمسی موجود استفاده می‌کند.

## ادامه فاز ۶

1. ثبت گردش وضعیت اشتراک و Audit مرکزی؛ راه‌اندازی trial برای سالن تازه با سیاست مشخص و قابل تغییر.
2. مدل مستقل درخواست خرید/تمدید، صورتحساب و تراکنش پلتفرم با کلید یکتا.
3. اتصال درگاه و اعتبارسنجی server-to-server، ضد replay، تطبیق مبلغ و ثبت اتمیک؛ بدون اتکا به callback مرورگر.
4. پنل مالک برای دیدن پلن، تاریخ انقضا، تاریخچه پرداخت و درخواست تمدید.
5. اجرای سیاست انقضا و تمدید با دوره ارفاق، بدون حذف داده؛ اعلان قابل کنترل و تست‌های concurrency.
6. آزمون‌های PostgreSQL، E2E مرورگر، سناریوهای پرداخت ناموفق و rollback قبل از فعال‌سازی.
